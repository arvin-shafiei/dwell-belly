# Eval results

Generated by `node scripts/eval/report.mjs` from saved eval runs. Not edited by hand.

How to read this: every case is run through the agent (`npm run eval -- --agent flow`), then scored against an answer key. Disposition and channel are checked in code; whether the right party was addressed, whether the content is right and whether a must-never rule was broken are judged by a model. Each score comes from one run, and the agent is not deterministic, so small differences between runs are noise.

## What these four runs are, and what they are not

- **The sample:** the same 48 cases in every run: 12 organiser practice cases and 36 generated cases (3 from each of 12 difficulty patterns). The full sets are 50 and 243.
- **Runs 1 and 2 only judged the first message the agent sent.** The agent usually sends two (one to the owning team, one to the person waiting). Run 3 judges every message, so its rule-break count is the first honest one, and runs 1 and 2 understate theirs by an unknown amount.
- **Each run changed several things at once.** Run 1 to run 2: the models (all Opus 5.5, then Opus for the deciding step and Sonnet 5.5 for reading and checking), the planner's guidance, and one eval rule (a request routed through a visible team is accepted when the answer key names a team that appears nowhere in what the agent is shown; 22 of the 50 practice keys do this). Run 2 to run 3: a tighter legal-threat rule, a retry for the message checker, a richer decision card, the three quick checks running in parallel, a planner rule against invented team names, and the eval judging every message. Differences between columns cannot be attributed to any one change.
- **Run 3 to run 4:** tighter guidance on extra messages, no reply to unverified requesters, no wait-before-using advice, no invented team names, shorter messages and a one-sentence decision line. Run 3's two rule breaks (`gen-801`, `gen-1004`) do not recur in run 4.
- **Run 4 is the code as merged at 14:05 on 10 October.** Its two failures are both escalations where the agent also sent one message and the judge scored that message, not the handover note: `gen-1201` (a bereaved relative; the agent told her a supervisor would decide) and `gen-904` (a welfare concern; the agent asked Dispatch to hold the parcel). Whether those are agent faults or the eval judging the wrong thing has not been settled.
- **One run each.** The agent is not deterministic, so a case can pass in one run and fail in the next; treat a difference of one or two cases between runs as noise.
- **Views:** practice cases were scored without their title and Context section, which often state the answer. The with-Context view (`--with-context`) has not been run through the eval.
- **Time and cost, measured separately:** one batch of all 50 practice cases, each cut at its escalation, 8 at a time, on the same models as runs 2 to 4: 50 of 50 answered, no failures, 165 s in total (17 to 32 s per case), $2.70 (about $0.054 per case). That batch was not scored.
- **Not run:** the 12 stress-test fixtures in `docs/stress-test/fixtures/` (including 109 and 111, which need a human) have not been put through this eval.
